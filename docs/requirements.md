# Requirements Specification – Fleet Manager

SE411 Project · Part 1 · Fall 2026–27

## 1. Purpose

Fleet Manager is a single-page React application that lets a company manage its **cars**.
Part 1 is frontend-only: data is kept in an in-memory collection of JavaScript objects
(no database). A Spring Boot backend will replace the in-memory store in Part 2.

## 2. Asset: Car

| Field         | Type    | Required | Rules                                                        |
| ------------- | ------- | -------- | ------------------------------------------------------------ |
| `id`          | number  | auto     | Unique, generated by the app                                 |
| `make`        | string  | yes      | e.g. Toyota                                                  |
| `model`       | string  | yes      | e.g. Camry                                                   |
| `year`        | number  | yes      | Between 1990 and next year                                   |
| `plateNumber` | string  | yes      | Stored upper-case; must be unique across the fleet           |
| `color`       | string  | yes      |                                                              |
| `fuelType`    | enum    | yes      | Petrol · Diesel · Hybrid · Electric                          |
| `mileage`     | number  | yes      | Kilometres, ≥ 0                                              |
| `status`      | enum    | yes      | Available · In Use · Maintenance · Retired                   |

## 3. Functional requirements

| ID   | Requirement                                                                                     | Brief ref. |
| ---- | ----------------------------------------------------------------------------------------------- | ---------- |
| FR1  | The project is a React application.                                                             | Req. 1     |
| FR2  | A menu is visible on every page and links to Cars, Add Car and About.                           | Req. 2     |
| FR3  | **Display** – the user can view all cars in a table.                                            | Req. 3     |

| FR6  | **Update** – the user can edit any car through the same form, pre-filled with its values.       | Req. 3     |
| FR7  | **Remove** – the user can delete a car after confirming the action.                             | Req. 3     |
| FR8  | The user can search cars by make, model, plate or color and filter by status.                   | extra      |

## 4. User stories

- **US1** – As a fleet manager, I want to see all cars in one list so I know what the company owns.
- **US2** – As a fleet manager, I want to add a car so new purchases are recorded.
- **US3** – As a fleet manager, I want to edit a car so its mileage and status stay up to date.
- **US4** – As a fleet manager, I want to delete a car (with a confirmation) so sold cars are removed without accidents.
- **US5** – As a fleet manager, I want to search and filter the list so I can find a car quickly.
- **US6** – As a visitor, I want an About page so I know who built the application.

### Acceptance criteria (examples)

- Submitting the add form with an empty required field shows an error and does not save.
- Adding a car with a plate number that already exists is rejected.
- After saving, the user returns to the list and sees the change immediately.
- Cancelling the delete confirmation keeps the car.

## 5. Non-functional requirements

- Runs in any modern browser; layout adapts to small screens.
- Form fields have labels and error messages are announced (`role="alert"`) for accessibility.
- Automated tests cover the data layer, the form and the main user flows.

## 6. Page outline / visual design

| Route             | Page        | Content                                                          |
| ----------------- | ----------- | ---------------------------------------------------------------- |
| `/cars`           | Car list    | Search box, status filter, table with Edit / Delete per row      |
| `/cars/new`       | Add car     | Car form (empty)                                                 |
| `/cars/:id`       | Car details | All fields, Edit and Delete buttons                              |
| `/cars/:id/edit`  | Edit car    | Car form (pre-filled)                                            |
| `/about`          | About       | Project description and team table                               |

Design: blue top navigation bar, white cards on a light-grey background, coloured status badges
(green = Available, blue = In Use, amber = Maintenance, grey = Retired).
